# 경기판 코스메틱 외형 적용 — UI V1.3 인수

관련 이슈: #165, 부모 #162. 선행 인벤토리 UI PR #167은 `develop` 병합. 기존 코스메틱 시스템 API #115 사용.

## 구현 범위

- 일반/랭크 `GameBoard`는 **본인** `GET /api/cosmetics/me`와 **상대** `GET /api/cosmetics/players/:id`를 각각 조회합니다. 닉네임/RP/승패/샷 서버 경로는 변경하지 않습니다.
- AI `AiGameBoard`에서는 본인 인벤토리만 조회합니다. AI는 DB 플레이어가 아니므로 공개 코스메틱 API 조회하지 않고 스타터 외형을 사용합니다.
- `GamePieces`: 공통 SVG 렌더링에서 기존 진영 테두리와 원형 위치·반경을 보존하면서 `piece-forest` 숲빛, `piece-starlight` 별빛 색·무늬를 추가합니다. `piece-classic`은 **원본 주황/파랑**을 그대로 사용합니다.
- `GameIdentityHeading`: 기존 플레이어 카드에 장착 캐릭터 미리보기(기본·청동·궤도)를 34px 이내 장식으로 표시합니다. 현재 턴·닉네임·남은 알·선공/후공은 그대로 유지합니다.
- 애니메이션 `board`는 기존 상태/리플레이 프레임 그대로 유지하며 외형 코드 매핑은 별도 hook에서 한 번 조회합니다.

## 오류·개인정보·운영

- Server Component에서 `process.env.COSMETICS_UI_ENABLED === 'true'`를 전달할 때만 클라이언트 조회가 활성화됩니다. **기본 OFF**.
- GET /me 또는 GET /players/:id가 401/404/503이거나 네트워크·JSON 파싱 실패, 비공개 사용자, 미등록 아이템 코드는 기본 알과 기본 캐릭터로 폴백합니다. **경기를 차단하지 않습니다.**
- 타인 비공개 프로필의 공개 로드아웃을 우회하여 읽지 않습니다. 공개 허용 여부는 기존 API/RLS가 판단합니다. 상대방의 보유 목록·해금 시각은 읽거나 보여주지 않습니다.
- CSS/SVG 디자인만 수정합니다. `RADIUS`, 800×500 보드, `piece.x/y`, 포인터 좌표·샷 `dx/dy`, 물리 판정, RP·서버 샷/AI 로직, DB migration 모두 변경 없음.
- 현재 SQL 009 운영 적용/실사용자 2계정 장착·비공개 폴백 E2E가 확인되지 않았으므로 기능 플래그는 운영에서 켜지 않습니다.
- 화면에 외형이 표시되는 것은 경기 결과를 바꾸는 기능이 아닙니다. 상대가 비공개이면 기본 디자인으로 보이는 제약이 있습니다.
