# ALEPH 중간 점검 2차(P2) / 최종 제출(P3) 입력 초안 — 2026-10-28

> 기존 P1 양식의 필드명(이번에 만든 것·확인 방법·바뀐 점·AI/내 판단·다음 일)을 기준으로 작성. 이후 ALEPH의 실제 P2/P3 화면 문구가 다르면 화면에 맞춰 조정합니다.

## P2 — 중간 점검 2차

### 이번에 만든 것
기존 초대방 일반전에 이어 랜덤 랭크 매칭과 Elo RP 정산, 리더보드 및 대전 기록을 구현했습니다. 비슷한 RP의 사용자끼리 매칭하고 대기·취소·만료를 처리하며 PostgreSQL 트랜잭션으로 중복 경기 생성을 방지합니다. 초기 RP 1,000, Elo K=32를 적용하고 랭크전 종료 시 RP·승패·이력을 한 번만 기록합니다. 일반전 결과는 랭크 점수에 영향을 주지 않습니다. 사용자 실제 기능 확인에서 정상 동작을 보고받았고, 운영 DB에서 랭크전 완료 1건과 정산 +16/-16을 확인했습니다.

### 확인하는 방법 · 3단계 이내
1. 결과물에 서로 다른 두 계정으로 로그인해 랭크 아레나에서 랜덤 매칭을 시작합니다.
2. 동일한 랭크 경기에 입장해 번갈아 알을 발사하고 한쪽이 승리하거나 기권하여 경기를 종료합니다.
3. 양쪽 RP·승패·리더보드·최근 경기의 변화를 확인하고, 일반전에서는 RP가 변하지 않는지 확인합니다.

### 바뀐 점과 그 이유
1차에는 친구 초대방 중심으로 서버 물리 판정과 실시간 턴 진행을 검증했습니다. 2차에는 원래 목표인 경쟁 기능을 위해 별도 랭크전 모드와 RP 정산·순위표를 추가했습니다. 대기열 중복 요청이나 한 경기의 중복 정산으로 순위가 왜곡되지 않도록 DB 트랜잭션·고유 제약·RLS를 적용했습니다.

### AI에게 맡긴 일과 내가 판단한 일
AI는 매칭 큐와 데이터베이스 트랜잭션, Elo 정산, 랭크 대시보드, 권한 검사와 자동화 테스트를 구현했습니다. 저는 일반전과 랭크전 분리, 경쟁 시스템의 필요성과 게임을 직접 사용할 때의 완성도를 판단했고, 기능을 실제로 확인해 정상 동작 여부를 점검했습니다.

### 다음에 할 일
재접속 복구, 턴 제한, 모바일·키보드 조작, 중복 요청 방지 등을 최종 단계에서 보완하고 보안 설정·사용성·운영 증빙을 정리하겠습니다.

## P3 — 최종 제출

### 이번에 만든 것
Next.js·Supabase·Vercel로 1:1 온라인 알까기 웹게임을 완성했습니다. 회원가입/로그인, 초대 코드 일반전, 서버 확정 5대5 물리 판정, 양측 턴 동기화, 알 이동 애니메이션, 게임판 오른쪽 턴 로그, 두 플레이어 동의 재대전을 제공하며 랜덤 랭크 매칭·Elo RP·TOP100 리더보드·전적을 추가했습니다. 마지막에는 경기 재접속 복구, 턴당 120초 서버 제한, 중복 정산 방지, 샷 요청 빈도 제한과 키보드 보조 조작을 반영했습니다. 사용자 실사용 점검에서 정상 동작을 확인받았으며 최신 Production 배포와 GitHub Actions가 성공했고 운영 DB 정산 내역도 일치했습니다.

### 확인하는 방법 · 3단계 이내
1. 서비스에 서로 다른 두 계정으로 로그인해 일반전 코드방 또는 랭크 랜덤 매칭을 시작합니다.
2. 번갈아 알을 발사해 이동 애니메이션·턴 로그·승패를 확인하고, 경기를 종료한 후 재대전 또는 RP·순위 반영을 확인합니다.
3. 진행 중 새로고침/재접속, 120초 턴 만료, 모바일 터치와 키보드 조작을 확인합니다.

### 바뀐 점과 그 이유
처음에는 기본 대전 기능 중심이었으나 실제 플레이에서 알이 순간이동하는 듯한 연출, 좌우 여백, 발사 세기와 화면 흔들림을 개선할 필요가 있었습니다. 이동 애니메이션·우측 턴 로그·재대전을 추가하고 게임판 높이를 고정했습니다. 또한 서버리스 환경에서도 상태가 유실되지 않도록 DB 스냅샷 복구, 턴 시간 제한과 원자적 RP 정산을 강화했습니다.

### AI에게 맡긴 일과 내가 판단한 일
AI는 프론트엔드·게임 로직·인증과 RLS·DB 마이그레이션·실시간 상태 동기화·테스트·배포 자동화를 구현했습니다. 저는 1:1 알까기라는 주제와 서비스 범위를 결정하고, 실제 사용 중 불편했던 턴 로그 위치·모션·세기·스크롤과 흔들림 문제를 발견해 개선을 요청했습니다. 수정 사항을 직접 확인하고 정상 작동 여부를 판단했습니다.

### 다음에 할 일
서비스 운영 과정에서 사용자 피드백을 수집하고 매칭 대기 시간·물리 밸런스·모바일 사용성을 지속 개선하겠습니다. 추가로 Supabase Auth 유출 비밀번호 보호 설정과 권한 함수 보안 점검, 동시 접속 규모 증가에 대한 성능 검증을 진행할 계획입니다.
