# AI 대전 — 대기실에서 AI 상대 추가 (P3 이후 기능)

## 사용자 결정 및 흐름
1. 로비의 기존 **방 만들기**를 누릅니다.
2. 대기실에서 친구가 입장하기 전 방 주인이 **AI 상대 추가**를 누르고 **쉬움·보통·어려움** 중 하나를 선택하여 **확인**합니다.
3. AI와 5:5 알까기 경기를 진행합니다. 인간 차례에서 샷을 발사하면 서버가 AI의 샷을 선택·판정하고, 화면에 두 발사의 프레임이 재생됩니다.
4. 종료 시 승패가 나타나고 **같은 난이도로 재도전** 또는 **로비로 돌아가기**를 선택합니다.

기존 초대방 일반전·랜덤 랭크전은 유지합니다. **AI 대전은 연습전이며 RP/리더보드에 반영하지 않습니다.**

## 설계
- 동일한 `rooms` 대기실을 사용하고, AI 추가 시 방을 잠근 뒤 `rooms.status='playing'`으로 변경. 친구 입장과 AI 시작은 방 행 잠금으로 직렬화.
- AI는 Supabase Auth 가짜 사용자로 생성하지 않고 `ai_matches` 전용 테이블과 상수 ID로만 표현. 게임당 1인 소유자만 RLS로 읽기.
- 서버에서 기존 `simulateShotWithFrames` 물리 엔진을 실행하고 `commit_ai_turn` 서버 전용 RPC가 사람+AI 결과를 한 번에 저장. 중복/낡은 턴은 거절.
- 난이도: 쉬움은 조준 오차가 있는 단일 후보, 보통은 제한된 후보 시뮬레이션, 어려움은 더 많은 후보와 내 알 생존 점수를 비교. 외부 LLM 비용은 없음.
- `ai_turns`에는 사람/AI 입력과 프레임 저장, 새로고침·복귀에도 상태 유지. 종료 후 기권 가능 및 새 방으로 재도전.
- 발사 요청은 인증된 사람의 서버 API에서 처리하고 AI 샷은 브라우저에서 직접 DB에 쓰지 않음.
- 인간 보드 입력: 드래그 및 키보드 지원, 모바일 반응형 레이아웃 적용.

## 테스트와 확인 방법
- `tests/ai-rooms-sql.test.ts`: 방 주인 권한, 친구 참가 경합, RLS, 잘못된 난이도, 중복 턴, 기권.
- `tests/ai-bot.test.ts`: 세 난이도별 유효 샷·결정성·물리 호환·입력 데이터 불변.
- `npm run check`, CI, Vercel Preview 및 Production 적용 후 사용자 실제 쉬움·보통·어려움 대전 테스트.
- 주의: 서버리스 함수 부하를 제한하기 위해 AI의 시뮬레이션 후보 수 상한을 둡니다. 대규모 동시 접속 부하 및 밸런스 튜닝은 별도 과제입니다.
