# Alkkagi Arena — UI/UX 리뉴얼 설계안 v1

> 작성: 2026-10-29 · 상태: **설계/이슈 계획 완료, 디자인 코드 미구현**  
> 참고 디자인: 사용자가 선택한 **4번째 귀여운 게임형 로비 시안**  
> 적용 대상: https://alkkagi-alpha.vercel.app · 저장소 https://github.com/SuperNova080710/Alkkagi  
> 상위 이슈: [#51 디자인 리뉴얼](https://github.com/SuperNova080710/Alkkagi/issues/51)  
> **중요:** 이 문서는 UI/UX 구현 계획이며 현재 서비스에 새 레이아웃이 적용됐다는 의미가 아닙니다.

## 1. 핵심 방향과 원칙

**키워드:** 작은 알의 큰 승부 · 캐주얼 보드게임 · 귀엽고 친숙한 알 캐릭터 · 따뜻한 크림·에메랄드·골드·우드.

- 로비가 단순한 링크 모음이 아니라 **게임 모드를 고르는 홈 화면**처럼 보여야 합니다.
- 캐릭터·나무·알 이미지는 **브랜드와 장식**이며, 실제 조작 UI의 대비·가독성·히트 영역을 해치지 않습니다.
- 기능은 **현재 구현된 것/추후 구현할 것**을 명확히 구분합니다. 비활성 예정 메뉴는 `준비 중`이라고 표시하고 존재하지 않는 통계·보상·알림 숫자를 만들지 않습니다.
- 플레이 진입은 한 번에 이해되도록 만들되, 기존 방 코드/인증/랭크 RP/서버 물리·턴 판정/재접속/채팅은 보존합니다.
- 대전 보드 위를 UI 오버레이가 가리지 않으며, 결과창과 작은 효과만 모션을 사용합니다.
- 지금의 P3 제출 문서·발표 산출물은 개정 요구가 없는 한 **변경하지 않습니다**.

## 3. 브랜드·디자인 시스템

### 3.1 색상 토큰 — 제안값

| 토큰 | 제안 색상 | 용도 |
| --- | --- | --- |
| `--bg-canvas` | `#F6EDDA` | 종이·크림 배경 |
| `--bg-card` | `#FFF9EC` | 상단 정보와 주요 카드 |
| `--color-forest` | `#174B36` | 헤더/브랜드/강한 텍스트 |
| `--color-jade` | `#25744F` | 일반전/기본 버튼 |
| `--color-gold` | `#E5A63A` | 랭크전/승리 메달 |
| `--color-sky` | `#297FA1` | AI전/파란 알 |
| `--color-wood` | `#734E35` | 테두리/나무판 효과 |
| `--color-ink` | `#292A24` | 본문 텍스트 |
| `--color-muted` | `#665F53` | 보조 텍스트 |
| `--color-danger` | `#A42C35` | 에러/패배 |

알의 실제 진영은 **기존 주황 `#F59E0B`, 파랑 `#60A5FA`**을 기준으로 유지합니다. 의미 색상을 바꿀 경우 색맹/대비 검증 후 적용합니다.

### 3.2 시각적 규칙

- **글꼴:** 본문은 한글 가독성이 좋은 산세리프(예: Pretendard/Noto Sans KR). 로고만 별도 입체·손글씨 느낌의 원본 아트 에셋. 이미지 속 한글을 중요한 버튼 문구에 의존하지 않습니다.
- **카드:** 크림색, 목재색 1px 윤곽과 부드러운 그림자. 기본 반경 16–20px, 모드 카드/히어로 24–28px.
- **버튼:** 44px 이상 터치 영역, 기본 에메랄드/랭크 골드/AI 하늘색. hover·focus-visible·disabled·loading의 차이를 명확히 표시.
- **알 마스코트:** 녹색(브랜드), 주황·파랑(대전 진영), 하늘색 로봇 AI. 각자 1–2개의 표정·포즈를 단계적으로 제작.
- **배경:** 목재/크림/게임판 원형 패턴을 약하게 활용. 플레이/폼 위에는 복잡한 질감을 깔지 않음.
- **모션:** 버튼 120–180ms, 카드 전환 160–220ms, 경기 결과 180/260ms 기존 연출 유지. `prefers-reduced-motion`에서는 없어지거나 단축.
- **접근성:** 상태 전달은 색상+텍스트+아이콘, 키보드 순서/포커스 링, 라벨, alt, 읽을 수 있는 대비(WCAG AA 목표).

## 4. 화면 구조 (와이어프레임)

### 4.1 랜딩 `/` — 신규/비로그인 유저

```text
┌────────────────────────────────────────────────────────┐
│ 로고                  게임 소개                  로그인 │
├────────────────────────────────────────────────────────┤
│                ALKKAGI ARENA                           │
│     웃는 알 캐릭터 · 나무판 · 귀여운 브랜드 일러스트      │
│         "작은 알 하나, 큰 승부 한 판!"                   │
│           [로그인]    [회원가입]                        │
├────────────────────────────────────────────────────────┤
│    친구와 일반전     RP 랭크전      AI 연습전            │
│  "설치 없이 브라우저에서 1:1 알까기"                    │
└────────────────────────────────────────────────────────┘
```

**중요한 우선 수정:** 현행 랜딩에 남아 있는 `개발 중 / 실제 플레이는 추후 제공됩니다` 문구는 현 서비스 상태와 다르므로 최신 기능 설명으로 교체합니다. 실제 플레이를 과장하는 접속자 수/누적 경기 수는 넣지 않습니다.

### 4.2 게임형 대전 로비 `/lobby` — 로그인 후 중심 화면

```text
┌─────────────────────────────────────────────────────────────────┐
│ 브랜드 로고       홈    게임하기    랭킹    친구(예정)   내 프로필 │
├─────────────────────────────────────────────────────────────────┤
│ 히어로: 웃는 녹색·주황·파랑 알 캐릭터 / 따뜻한 나무 게임판        │
│ "지금 한 판 어때요?"         [게임 모드 선택으로 이동]            │
├─────────────────────────────────────────────────────────────────┤
│ [ 일반전 ]          [ 랭크전 ]           [ AI 대전 ]             │
│ [방 만들기/참가]    [매칭 화면]           [난이도 선택]           │
├─────────────────────────────────────────────────────────────────┤
│ 진행 중인 경기(실데이터)      │  리더보드 TOP 3(실제 RP)          │
├─────────────────────────────────────────────────────────────────┤
│ 내 닉네임·RP / 프로필        │  앞으로 추가할 기능: 준비 중     │
└─────────────────────────────────────────────────────────────────┘
```

- 상단 첫 번째 CTA는 **게임 모드 카드로 스크롤/포커스 이동**. 존재하지 않는 즉시 매칭을 실행하지 않음.
- 일반전 카드: 친구와 방 생성·8자리 코드 입장을 고르는 모달/패널.
- 랭크전 카드: `/ranked`로 이동하거나 현 매칭 큐 상태를 그대로 보여주는 랭크 허브로 이동.
- AI 대전 카드: 쉬움·보통·어려움 선택 뒤 `확인`. 서버에서 기존 RPC 두 개를 순차 실행해 즉시 게임.
- 진행 중 일반전/AI전 복귀 링크는 **원래 쿼리와 소유권 검증 유지**, 아무 경기 없으면 빈 상태 안내.
- TOP3는 기존 `ranked_dashboard` 데이터에서 파생. 실패·비로그인·빈 기록에서 허구의 RP/닉네임 노출 금지.
- 미래 기능(친구·메신저·꾸미기)은 `준비 중` 태그와 함께 소개 가능하지만 **비활성 상태**이며 가짜 팝업/허구 숫자를 표시하지 않음.

### 4.3 모드 선택 대화상자·대기실

**일반전 모드 카드**
- `방 만들기`: 현재 `createRoom` 실행, 대기실에서 초대 코드 복사/친구 입장 대기.
- `초대 코드로 참가`: 기존 `joinRoom` 연결, 잘못된 코드/방 만료/이미 참가 등의 서버 오류 표기.

**랭크전 모드 카드**
- 현행 `/ranked`의 RP·TOP100·대기열 상태를 보여줍니다.
- `매칭 시작`은 현재 `RankedQueue` 서버 동작을 재사용하고 중복 제출·이동 시 상태를 유지합니다.

**AI 모드 카드**
- 난이도 선택 모달: `쉬움 · 보통 · 어려움`, 세 난이도에 대한 한 문장 설명, `확인·AI 대전 시작`.
- 확인 후 잠금/로딩 → `create_casual_room` → `start_ai_room` → `/rooms/[id]/ai`.
- 실패 시 중복 생성 방지, 이미 생성된 방 복귀 경로 제공, 서버에서 상태를 진실의 원천으로 검증.
- 기존 `/rooms/[id]`의 호스트 전용 AI 상대 추가 폼은 **고급 진입 경로로 유지**합니다.

**대기실 `/rooms/[id]`**
- 좌측: 초대 코드 큰 카드/복사, 참가자 1·2 슬롯(선공/후공), 준비 상태.
- 우측: 방 주인에게 `경기 시작` 또는 `AI 상대 추가`(친구 미입장 시), `방 닫기`; 다른 사용자에게 `방 나가기`.
- 대기실을 귀여운 캐릭터/UI로 꾸며도 RLS/소유자 판단과 기존 두 사용자 대전 진입 조건은 그대로 둡니다.

### 4.4 일반전·랭크전·AI전 게임 화면

```text
┌────────────────────────────────────────────────────────────────┐
│ 왼쪽 선수(주황)     현재 턴·남은 알      오른쪽 선수(파랑)      │
├──────────────────┬──────────────────────────┬───────────────────┤
│ 경기 채팅        │                          │ 턴 기록           │
│ [메시지 목록]    │      나무판·알까기 보드  │ [샷 기록 목록]    │
│ [입력창/전송]    │                          │                   │
├──────────────────┴──────────────────────────┴───────────────────┤
│ 조작 안내 / 키보드 대체 수단 / 제한시간 / 기권                 │
└────────────────────────────────────────────────────────────────┘
```

- 데스크톱에서는 기존 3열 **채팅 | 보드 | 턴 로그**를 유지하며 고정 보드 비율 `800:500`과 SVG 포인터 좌표 계산을 건드리지 않습니다.
- 모바일에서는 **상단 상태 → 게임판 → 조작 → 채팅 → 턴 기록** 순. 채팅·기록은 독립 스크롤/접기 가능하게 검토합니다.
- 알의 `나` 표식·상단 팀 색상 안내를 유지하고 보드 위 큰 라벨/추가 링/이펙트로 판을 가리지 않습니다.
- 게임 종료 시 결과 카드에 **승패/무승부, 랭크면 실제 rating_history ΔRP, 로비, 재도전**. 일반전은 양측 합의, 랭크전은 새 매칭, AI전은 같은 난이도 시작.
- 엔터 전송·Shift+Enter 줄바꿈·한글 IME·전송 후 포커스와 서버 채팅 권한을 그대로 유지합니다.
- AI전은 참가자용 대화창 대신 **AI 난이도·안내 카드**, AI 발사 중 상태, 같은 난이도 재도전을 보여줍니다. RP는 변동하지 않습니다.

### 4.5 랭킹·내 프로필

**랭크 `/ranked`**
- 상단: 실제 닉네임·현재 RP·전체 순위·승패 수치가 들어간 메달 스타일 카드.
- 중심: 기존 매칭 버튼 및 큐 상태.
- 아래: TOP100 리더보드와 최근 전적. **계절/시즌 레이팅과 티어 뱃지는 현재 없음**: 입체 시즌 보상을 시안처럼 표시하지 않음.

**내 프로필 `/profile`**
- 지금 구현된 정보: 닉네임(변경·중복 확인), 현재 RP.
- 향후 확장 슬롯: 대표 캐릭터·선택한 알 스킨·레벨/XP·친구 및 경기 기록.
- 아직 준비되지 않은 항목은 `준비 중`이나 적절한 설명으로 비활성화. 가상의 Lv.12·포인트·보유 아이템 표시 금지.
- 향후 타인 프로필은 닉네임/공개 범위/RLS·친구 관계 정책을 설계한 뒤 별도 경로 추가.

## 7. 반응형 및 상태 설계

- **≥ 1280px:** 상단 내비 + 넓은 히어로 + 3개 모드 카드 + 2~3개 보조 패널. 경기 화면은 기존 3열 고정 높이 규칙을 유지.
- **768–1279px:** 히어로·카드 압축, 모드 카드 2열 또는 세로; 게임판을 먼저 보이게 하고 채팅/턴 로그는 아래나 접이식.
- **≤ 767px:** 모바일 1열, 헤더 메뉴 압축, CTA 최소 44px, 게임판 전체 폭·비율 보존. 모달이 키보드에 가려지지 않게 스크롤.
- **저성능/느린 네트워크:** 이미지 늦게 로딩돼도 레이아웃 이동 방지, 로딩 스켈레톤/에러·재시도 표시.
- **빈 상태:** 진행 중 경기 0건, 아직 랭크 전적이 없음, 프로필 조회 실패, AI 시작 실패 등은 실제 상태에 맞춘 간결한 메시지.
- **접근성:** 실시간 상태는 `aria-live` 남용 없이, 키보드 초점 유지, 눈에 띄는 포커스, 색상 외 추가 텍스트 제공.
- **모션 줄이기:** `prefers-reduced-motion` 감지. 승패 카드·마스코트 진입 연출을 줄이고 게임 물리의 결과 확인 기능은 유지.

## 8. 검증 시나리오와 완료 정의

**공통:**
- [ ] UI가 게임판/채팅/버튼을 가리지 않고 390×844, 768×1024, 1366×768, 1440×900 뷰포트에서 가로 스크롤·레이아웃 점프 없음
- [ ] 닉네임 설정·대소문자 중복/로그인/회원가입·로그아웃 정상
- [ ] 이미 구현된 게임 모드와 예정 기능을 시각적으로 구분, 미구현 메뉴에 활성 링크/허위 수치 없음
- [ ] 서버리스 물리 판정/턴/RLS/원자적 랭크 RP 정산 및 Supabase Realtime 기존 테스트 유지

**일반전:** 두 계정 입장 → 턴/알 표기 → 채팅(Enter/Shift+Enter/한글/포커스) → 승패 → 양측 동의 재대전.

**랭크전:** 두 계정 매칭 → 게임 종료 → 각자 실제 RP ±와 리더보드·전적 일치, 일반전/AI전은 RP 영향 없음.

**AI 연습전:** 로비 카드에서 난이도 선택 → 자동 방 생성 → AI 3단계 응수·애니메이션 → 재도전·경기 복귀. 기존 대기실 AI 추가 경로도 동작.

**제출·운영 경계:** 이 문서는 **새 UI 구현 계획**입니다. 코드/CI/Preview/Production 반영 여부는 각 후속 PR에서 증빙하고, ALEPH P3 최종 제출 접수·승인과 혼동하지 않습니다.
