# P3 진행 — 턴 만료와 재접속 안정화

## 서버 기준 턴 기한
- `matches.turn_deadline`: PostgreSQL 시각 기준 **신규 경기와 새로운 턴부터** 120초. 적용 이전부터 진행 중이던 경기는 마이그레이션만으로 강제 만료시키지 않습니다.
- `commit_casual_shot`: 행 잠금 후 서버 시각 기한 검증. 만료 후 발사를 받아들이지 않음.
- `expire_match`: service role 전용, 매치 잠금 후 서버에서 실제로 만료됐는지 재검사. 미만료 시 아무것도 변경하지 않음.
- 만료 시 현재 턴 소유자가 패배하며, 랭크전이면 같은 트랜잭션에서 RP·전적·이력 정산.
- 이미 종료된 매치나 중복 만료 시 상태를 다시 변경하지 않음.
- 브라우저가 연결 중일 때 기한 확인 후 API를 호출하며, 새로고침/복귀 시 서버 스냅샷과 기한을 다시 읽습니다.

## 복구 및 주의
- 연결이 끊어져도 경기판 및 턴/샷은 PostgreSQL에 저장됩니다.
- 다시 로그인해 방으로 돌아오거나 랭크 로비에서 활성 랭크 경기로 복귀할 수 있습니다.
- 두 플레이어 모두 접속하지 않으면 브라우저 타이머가 호출되지 않으므로, 기한이 지난 경기는 한 명이 돌아와 조회할 때 확정됩니다.
- 서버리스 환경에서 지속 연결만 믿지 않도록 기존 3.5초 폴링과 Realtime을 함께 유지합니다.
- 보안 경계: 사용자는 만료 API를 호출할 수 있지만 만료 여부, 승자, 점수 모두 DB 서버에서 결정합니다.

## 추가 보안과 조작 접근성
- `shot_rate_limits`: service-role 전용 사용자별 350ms 샷 계산 요청 간격. 서버 물리 계산 전에 처리하며 과도한 요청에는 429를 응답합니다.
- `claim_shot_slot`: PostgreSQL UPSERT의 조건부 갱신으로 여러 서버 인스턴스에 걸쳐 동일 기준 적용. 인증되지 않은 클라이언트는 실행할 수 없습니다.
- 마우스·터치 외에도 게임 우측 패널에서 **키보드 조작**을 펼쳐 알/8방향/세기를 선택하고 발사할 수 있습니다. 발사는 동일한 서버 권한·물리 판정을 통과합니다.
- 보조 조작이 펼쳐져도 게임판 높이를 바꾸지 않으며 사이드 패널 자체에 스크롤을 허용합니다.
- migration 008(턴 만료), migration 009(요청 제한)이 필요합니다.

1. A/B 대전 중 새로고침해도 동일 게임판·턴·남은 시간 복구.

3. 두 계정에서 만료를 동시에 요청해도 랭크 점수 한 번만 갱신.
4. 다른 사용자가 게임 API에 접근할 수 없어야 함.
