# ALEPH P2 — 랜덤 랭크 매칭 및 RP 정산

## 구현 범위
- 랭크 큐: `ranked_queue`에 사용자당 최대 1개 행. 새 계정의 RP 기본값은 1000.
- 2명의 대기자를 **PostgreSQL 단일 행 잠금**으로 직렬화해 동일 사용자의 중복 매치를 방지.
- 대기자 heartbeat는 3.5초 재조회로 갱신. 서버 시각 기준 45초 동안 응답 없는 항목 만료.
- RP 차이가 기본 200 이내, 30초 이상 대기한 사용자와는 400 이내로 매칭 폭 확장.
- 랭크 전용 새 매치는 `room_id=NULL`이며 일반전 초대 코드 방과 분리.
- 각자 5개의 알, 동일한 서버 물리 및 샷 판정, 승패/기권 처리.
- Elo: 초기 RP 1000 / K=32 / 기대 승률 `1/(1+10^((상대RP-내RP)/400))`.
- 경기 종료 DB 트랜잭션 안에서 프로필 RP·승패·무 전적 및 경기별 2개 `rating_history` 행을 원자적으로 기록.
- `rating_history`의 `PRIMARY KEY(match_id,user_id)`와 경기 잠금으로 중복 정산 방지.
- 일반전은 랭크 정산 함수를 호출하지 않아 RP 변동 없음.
- 로그인 사용자에게 리더보드 TOP 100, 내 순위, 최근 20개의 랭크 경기 제공.

## 보안
- `public.ranked_queue`: RLS 활성화, 클라이언트 SELECT/INSERT/UPDATE/DELETE 전부 금지.
- `public.rating_history`: RLS 활성화, 로그인 사용자 본인 이력만 SELECT 가능, 클라이언트 쓰기 금지.
- 내부 정산은 API 미노출 `private` 스키마의 함수이며 `authenticated`와 `service_role`의 직접 실행 권한을 모두 회수.
- 공개 RPC는 `auth.uid()`로 인증·참가 여부 확인. 클라이언트가 임의 RP/매칭 대상을 지정할 수 없음.
- 랭크 게임은 서버가 검증된 `user.id`에 대해 기존 DB 행 잠금과 서버 계산 결과로만 커밋.

## 검증
```bash
npm ci
npm run check
```
PGlite DB 통합 테스트에서 본인 큐 중복 가입·A/B 동일 match id·제3자 접근 거부·취소·정산 유일성·일반전 점수 유지 확인.

## 실제 서비스 E2E
1. A/B 서로 다른 계정으로 로그인하여 랭크 아레나에서 큐 등록.
2. 같은 랭크 매치 진입 후 드래그로 번갈아 플레이, 최종 결과 정산.
3. A/B의 RP가 ±16(동일 RP 시작/승패 기준), 전적 및 랭크 이력과 TOP100 표시에 일치하는지 확인.
4. 세 번째 탭의 중복 등록, 큐 취소, 새로고침/연결 끊김 재진입 및 일반전 RP 미변동을 추가 확인.

**주의:** CI/Preview 검증과 실제 두 브라우저 E2E는 서로 다른 증빙입니다. 후자는 완료 전에 실제로 재현해야 합니다.
