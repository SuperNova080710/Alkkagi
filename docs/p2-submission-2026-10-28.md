## 이번에 만든 것

1차에는 로그인과 초대 코드로 두 계정이 만나는 1:1 일반전을 구현했습니다. 이후 **랜덤 랭크 매칭**, Elo 기반 RP 정산, TOP 100 리더보드, 내 순위와 대전 기록을 추가해 계획했던 핵심 경쟁 기능을 구현했습니다. 랭크전에는 초기 RP 1,000과 Elo K=32를 적용하고, 승패와 점수 정산이 한 번만 처리되도록 PostgreSQL 트랜잭션과 고유 제약을 사용했습니다. 초대방 일반전은 랭크 점수에 영향을 주지 않습니다.

실제 플레이 과정에서 **양측 동의 재대전, 턴별 발사자와 양측 탈락 알 개수가 표시되는 오른쪽 로그, 서버 확정 궤적의 이동 애니메이션**을 추가했습니다. 게임판 스크롤·턴 중 화면 흔들림도 수정하고, 발사 세기를 조정했습니다.

현재 배포본에는 **경기 재접속, 서버 기준 120초 턴 제한, 샷 요청 빈도 제한, 모바일 터치와 키보드 보조 조작**도 반영돼 있습니다. 이 기능들은 최종 제출 전 개선의 기초가 되는 현 단계의 구현 결과입니다.

사용자가 직접 기능을 확인해 정상 동작한다고 보고했습니다. GitHub Actions 전체 검사가 성공했고 Vercel Production 배포가 READY입니다. 운영 DB에는 **완료 일반전 6건, 완료 랭크전 1건, 한 경기의 RP 정산 2건(+16/-16)**이 기록돼 있습니다.

## 확인하는 방법 · 3단계 이내

1. 공개 서비스에 서로 다른 두 계정으로 로그인해 **랭크 아레나 → 랜덤 매칭**을 시작하거나, 초대 코드를 이용해 일반전 방에 입장합니다.
2. 두 계정으로 번갈아 알을 발사하면서 **이동 애니메이션·턴 로그·경기 종료**를 확인합니다. 일반전은 두 플레이어가 다시하기에 동의하면 새 경기가 시작됩니다.
3. 랭크전 종료 후 **RP·승패·리더보드·대전 기록**이 일치하는지 확인합니다. 재접속 시 경기 복귀, 턴 제한, 모바일·키보드 조작도 확인할 수 있습니다.

## 바뀐 점과 그 이유

초기 계획은 1:1 대전과 방 만들기, 랜덤 랭크 매칭, 포인트·순위 경쟁이었습니다. 1차 점검에서는 안정적인 일반전 구현에 집중했고, 이번 단계에서 랭크전과 경쟁 기능을 추가했습니다.

플레이 결과만 즉시 표시하는 방식은 게임다운 느낌이 부족하고 화면 여백도 비효율적이었습니다. 이에 알의 **이동 모션**, 오른쪽 **턴 로그**, **재대전**을 추가했습니다. 실제 플레이 중 발견한 스크롤·화면 흔들림도 개선했습니다. 또한 서버리스 환경에서 경기 상태가 유지되도록 DB 확정 상태를 기준으로 복원하고, 중복 매칭·턴 처리·RP 정산을 방지했습니다.

## AI에게 맡긴 일과 내가 판단한 일

AI에게 Next.js 화면, 서버 물리 엔진, Supabase 인증·DB/RLS, 랜덤 매칭과 Elo 정산, 재접속·턴 제한, 자동화 테스트, Vercel 배포 구현을 맡겼습니다.

저는 **1:1 알까기·친구 대전·랜덤 랭크 경쟁이라는 주제와 범위**를 결정했습니다. 실제 플레이하면서 게임의 재미와 사용성을 기준으로 **재대전, 로그 위치, 이동 모션, 세기, 화면 스크롤·흔들림** 문제를 발견해 수정 방향을 정했습니다. 구현 후 직접 게임을 이용해 정상 동작 여부를 확인했고, AI의 자동화 테스트 결과와 운영 DB의 점수 기록도 대조했습니다.
