# 사용자 닉네임 설정 — P3 동료 테스트 개선 (2026-10-28)

## 요구 사항과 적용
- 회원가입 뒤 자동으로 생성된 닉네임을 `/profile`에서 변경 가능
- 한글 완성형/영문/숫자/밑줄(_)만 사용, **2~24자**, 공백·HTML 기호 제외
- **중복 확인** 버튼으로 사용 가능 여부를 검사하고, 확인된 동일 입력값만 저장
- 대소문자 무관 `lower(nickname)` **UNIQUE INDEX**로 동시 저장 경합에도 중복 불가능
- 저장 RPC에서 `auth.uid()`로 본인 프로필만 변경; 타인 프로필/RP 직접 갱신 권한 없음
- 사용자/상대 닉네임은 기존 DB 응답을 통해 **일반전 대기실·게임 상단·턴 로그·랭크전·TOP100/최근 전적**에 노출
- 게임 진행 중 다른 탭에서 닉네임 변경 시 다음 페이지 새로고침 또는 3.5초 상태 재조회로 반영
- 이전 경기/스코어/기존 계정 이름은 migration에서 수정하지 않음

## 적용 항목
- `supabase/migrations/202610280010_profile_nickname.sql`: DB 형식·고유성/중복 확인·저장 RPC
- `/profile`: 현재 닉네임·RP/검사/변경 폼, 로비 및 랭크전 진입 버튼
- `tests/nickname-sql.test.ts`: PostgreSQL(PGlite) 실제 SQL/RLS/중복/리더보드/방 참가 이름 검증
- `tests/nickname-form.test.tsx`: SSR 폼 기본 상태·저장 제한

## 검증 시나리오
1. 계정 A/B 각각 다른 닉네임 설정 → 로비·게임 시작·턴 로그·리더보드에서 일치.
2. B가 A와 동일하거나 대소문자만 다른 닉네임 검사 → '이미 사용 중'.
3. 검사 후 다른 계정이 먼저 저장해도 최종 저장은 DB 고유성에 의해 거절.
4. 계정 A가 닉네임을 바꿔도 기존 RP·승패·최근 경기 기록 유지.
5. 게임 중 다른 탭에서 닉네임 변경 후 새로고침 → 최신 이름 표시.
